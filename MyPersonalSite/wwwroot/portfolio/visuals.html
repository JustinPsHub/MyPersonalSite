              Processing rules & demonstration limits
              

                Synthetic order deliveries are attributed to the same five service labels and dates used by the workspace filters. They illustrate processing; their amounts are not derived from service request counts or the latency model. Each service and date has twelve deliveries. Service, reporting window and date filter this dataset; selecting a delivery filters its measures. Stage previews distinguish unvalidated, validated and deduplicated values. USD only. Amounts
                must be nonnegative safe integers in cents. The first valid
                event for an ID wins; repeated IDs are skipped, and invalid
                events are quarantined. Totals use integer cents, then display
                dollars. No backend, queue, authentication, payment or network
                request is involved. Replay animates the same deterministic
                result; no data is persisted.

                Model assumptions & data definitions
                

                  Illustrative sensitivity analysis, not a forecast. Added
                  latency propagates through the directed call graph using fixed
                  synchronous exposure weights: gateway → data 65%; gateway →
                  identity 35%; data → storage 80%; identity → storage 50%.
                  Asynchronous telemetry has zero latency exposure. Portfolio
                  impact is weighted by selected request volumes. Throughput and
                  failure rates stay fixed; queueing, retries, and saturation
                  are not modeled. Metrics count service-level requests, so one
                  user action may contribute to several services. All records
                  and service relationships are synthetic.
