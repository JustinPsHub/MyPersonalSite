Contracts & Simulation Rules

Events require a nonempty ID, the order.created type, USD currency, and a nonnegative safe integer amount in cents. Accepted events are transformed into a canonical analytics payload.

The first valid event for each ID is delivered once per run; later valid deliveries with that ID are skipped. Invalid events never reserve an ID. The burst fixture includes 80 deliverable events, 10 contract violations, and 10 repeated deliveries.

Payloads, routing results, and rejected events remain in browser memory. Delivery destinations and dead-letter handling are simulated. Each preset starts a new run; Reset clears the run.

Burst mode demonstrates batch processing and outcome reconciliation. It does not represent server throughput. Network brokers, retry scheduling, and durable persistence are outside this simulation.
